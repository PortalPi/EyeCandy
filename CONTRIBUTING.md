# Contributing to Eye Candy

Eye Candy is a World of Warcraft: Forever addon. It exposes the game's standard and hidden graphics settings, curated presets ("Looks"), shareable named presets and dated backups.

## Layout

```
EyeCandy/   the addon. Load order is in EyeCandy.toc.
            Report.lua    /ec report: bug report text and Lua error capture
            Data.lua      tiers, Looks, Situations and the list of settings
            Core.lua      start-up, slash commands, applying and keeping settings
            UI.lua        the tabbed window and shared widgets
            Advanced.lua  the Hidden tab
            Standard.lua  the Standard tab (the game's Graphics menu)
            Presets.lua   named presets, import and export
            Backups.lua   backups and restore, and today's steps for Back to before
            Steps.lua     the Today list of steps on the Presets tab, each with its own Back
            Minimap.lua   minimap button, addon menu entry, Options > AddOns panel
            Peek.lua, Compare.lua   hide the UI to see the world; flip between before and now
            Situations.lua  the city and instance switches: lower costs in a capital city or a dungeon, raid, battleground or arena, put them back on leaving
            Autotune.lua, AutotuneTab.lua   the experimental Autotune and its Experimental tab
            PatchWatch.lua  the warning when settings changed while the game was closed
            Helper.lua    Help me pick: one question on the Presets tab, then one preset or Autotune
            FPS.lua       the FPS reader (ns.FPS), the live FPS on the bottom bar, each preset's last FPS
            EyeTest.lua   the eye test, a part of the Experimental tab
            PhotoMode.lua photo mode, a part of the Experimental tab
tests/      lib.py (shared helpers), harness.lua (a stand-in for the game), test_<area>.py (one per area), run.py (the older full suite)
docs/       cvar_audit.txt: Blizzard's help text and defaults for each setting
media/      logo/EyeCandy.png and EyeCandy.psd. Not shipped.
.github/    workflows/tests.yml (manual), workflows/release.yml (tag push), ISSUE_TEMPLATE/bug.yml
.pkgmeta, CHANGELOG.md   what the BigWigs packager ships. CHANGELOG.md is the players' notes.
```

## Dev loop

- Link `EyeCandy/` into `World of Warcraft\_forever_\Interface\AddOns\EyeCandy` with a directory junction (`cmd /c mklink /J "<AddOns>\EyeCandy" "<repo>\EyeCandy"`). The game then runs whatever is in the repo. The folder name must equal the .toc name.
- Edits are live in game after `/reload`. A .toc change needs a full game restart.
- Saved settings live in `WTF\Account\<ACCOUNT>\SavedVariables\<FolderName>.lua`, named after the addon folder. Renaming the folder starts with an empty file unless the old one is copied across.
- Tests: `pip install -r tests/requirements.txt`, then `python tests/test_<area>.py` for the area you changed. Each prints PASS or FAIL per check and "ALL PASS" at the end. They run in Python with Lua 5.1 stubs, so nothing in the game itself is tested.

## Game and API facts (checked Nov 2026)

- Client 1.60.1, `## Interface: 16001`. A retail-based engine with Midnight-era addon restrictions ("secret values"). None of the graphics CVars we use are secure, and `SetCVar` works for them out of combat.
- Useful APIs: `C_CVar.GetCVarInfo`, `SetCVar`, `ConsoleGetAllCommands` (help text), `IsGraphicsSettingValueSupported`, `GetMinRenderScale` and `GetMaxRenderScale` (0.33 to 2), `C_VideoOptions`, `Settings.RegisterCanvasLayoutCategory`, `MinimalSliderWithSteppersTemplate`.
- Import and export: `C_EncodingUtil` has `SerializeCBOR`, `DeserializeCBOR`, `CompressString`, `DecompressString` (Deflate), `EncodeBase64` and `DecodeBase64`. No external libraries are needed.
- Addons have no network access. A bug report is a copy-paste string.
- References: the Blizzard UI source mirror Gethe/wow-ui-source (branch `forever`); Ketho/BlizzardInterfaceResources (branch `forever`), files `Resources/CVars.lua` and `Resources/GlobalStrings/enUS.lua` (`OPTION_TOOLTIP_*`); Intel's ASSAO documentation for the `assao*` CVars.

## Rules

- Tooltips quote Blizzard's help text first, then one plain-English line, then the game default. If there is no official text, say "Not documented by Blizzard". Never present a guess as fact; mark it "Unconfirmed".
- Player-facing text uses British spelling, no em-dashes and short sentences.
- Every screen, button and line of player text follows `docs/ui-rules.md`. A pull request that adds or changes UI goes through its checklist first.
- Import only applies CVars on the addon's own whitelist. It skips and lists anything else.
- Never change settings in combat. Queue the change until `PLAYER_REGEN_ENABLED`.
- Add a check for every bug fixed. A change adds its checks in its own `tests/test_<area>.py` and runs that file.
- A feature that needs live FPS watches `ns.FPS` (FPS.lua), not an `OnUpdate` of its own, and unwatches when it is done. Autotune keeps its own, as it needs every frame's time.
- Bump `## Version` in the .toc for every release. A tag must match it, and a `-dev` version never ships.
- A new part of the Experimental tab goes in its own file and adds itself with `ns.AddExperiment` (AutotuneTab.lua). Anything in it that changes settings saves yours first, puts them back on a fight, a loading screen or closing the window, and never runs while another part has them.

## How the pieces work

- **Window.** Five tabs: Presets (opens first), Standard, Hidden, Backups and Experimental. The bottom bar has Apply (on the Hidden tab and the shrunk bar only, where it does something), Create backup (not on the Backups tab, which has its own), Keep my settings applied, the live FPS (see Live FPS below) and Copy my settings (`PlaceBottomBar` in UI.lua; checks in `tests/test_bar_tidy.py`). Every window drags, and a bottom-right grip scales it from 60% to 130% with the top-left fixed. Spot and scale are remembered per account in `EyeCandyDB.windows[name]` (`MakeWindow` in UI.lua; checks in `tests/test_window_scale.py`).
- **Shrink and fade.** A minus button shrinks the main window to a small bar with Apply (`ns.ToggleShrink`, checks in `tests/test_shrink.py`). After a second without the mouse over it the window fades to 70%, never while typing in it or scaling it; `/ec fade` turns that off (`ns.FadeStep`, checks in `tests/test_fade.py`).
- **City switch.** Off by default; `/ec city` or `ns.SetAutoSituation("city", on)` turns it on. In a capital city it lowers the Capital city Situation's `auto.caps` (Data.lua) where yours are higher, and puts each back on leaving unless you changed it there. A city is a map with the `IsCityMap` flag (there is no City map type), a known capital map id, or a "sanctuary" from `C_PvP.GetZonePVPInfo` (the bare `GetZonePVPInfo` is gone); never inside an instance. It waits out combat and takes no backup. `ns.KeepSituationLowered(fn, ...)` wraps every apply (`ns.ApplyAll`, and a preset of yours) and every restore (Back included): whatever they raised in a city is lowered again, and a setting you raised yourself is left alone. A Compare ends before the switch changes anything. `ns.SituationValue(cvar, value)` gives your own value for a lowered setting. Backups, saved presets, a restore's change count and Back's check use it (`Capture` in Backups.lua, `Snapshot` in Presets.lua), so none of them records the lowered ones as yours. Checks in `tests/test_situations_auto.py`.
- **Instance switch.** The city switch's machinery, for Raid & PvP. Off by default; `/ec instance`, the tick box under Raid & PvP, or `ns.SetAutoSituation("raid", on)`. In a dungeon, raid, battleground or arena (`ns.InstanceType`: `IsInInstance`'s type is `party`, `raid`, `pvp` or `arena`; housing's `neighborhood` and `interior`, and `scenario`, never count) it lowers Raid & PvP's `auto.caps` (Data.lua, its own values, only settings that cost more when higher) where yours are higher, and puts each back on leaving unless you changed it inside. `situationActive.place` keeps the type, so dungeon to raid starts again. It waits out combat only when a switch is due (the tick box then says so, `ns.SituationWaiting`) and Autotune (`ns.Autotune.IsRunning`), ends a Compare first and takes no backup. With nothing to lower, the card and title say nothing (`ns.SituationNote` gives false) and the box says "Nothing needed lowering". An instance is never a city, so the two switches never overlap; leaving one for the other puts back first. The game's own Raid and Battleground settings (`RAIDsettingsEnabled`): the game uses its `raidGraphics*` twin of each graphics menu setting in a raid or battleground, so there Eye Candy leaves those to the game and lowers only the rest. Dungeons are not covered by them (a player report) and arenas are unconfirmed, so there it lowers as usual. Checks in `tests/test_instance_switch.py`.
- **Peek and Compare.** Peek hides the UI. Compare flips between before your last preset (its step in today's list) and now, and the Peek bar can do the same. A backup or a new step never records "before" (checks in `tests/test_peek.py` and `tests/test_bar_buttons.py`).
- **Presets.** Built-ins are read-only (6 tiers, 5 Looks, 4 Situations). User presets can be saved, renamed, duplicated and deleted. A share string is `!EC1!` plus Base64(Deflate(CBOR)) with name, author, date and game version. Import shows a preview, handles a name clash (Replace or Keep both) and applies the whitelist. Settings a string leaves out go to the game default (`Presets.lua`).
- **Backups.** Original (kept for good, made once, at first login) and Manual (named). Nothing makes a backup by itself: not a preset, Apply, import or restore. Restore shows a change count and takes no backup of where you are; it is one of today's steps, so Back can undo it. Its result shows on the Backups tab's result line until you leave the tab; `/ec restore` prints it instead (`ns.RestoredLine`). Automatic backups from test builds are removed at load (`Backups.lua`, checks in `tests/test_backups.py`).
- **Back to before: today's steps.** Each preset (built-in, your own, an import, Autotune's result once saved as a preset) and each restore from the Backups tab is a step in `EyeCandyDB.steps`, newest first, with the settings and choices from just before it and what it left (`ns.NoteBeforeStep` in Backups.lua). Settings you change yourself after a step show as "Your own changes" at the top, and are saved as a step of their own when the next step starts; changes Compare or Autotune make are not yours. Steps are kept for the day and at most 10 (`ns.STEPS_MAX`). They are never backups. The Presets tab lists them under Today, above Your presets: the newest three, Show all for the rest (`Steps.lua`). Each row's Back asks first with the count (`ns.CountStepChanges`), then puts back the settings from just before that step; that step and every newer one leave the list, and you are on the preset you were on before it (`ns.GoBack` in Presets.lua, `ns.RestoreStep` in Backups.lua). Going back is not a step, so it can't be undone. A restore sets no preset as on. Back's result shows on the Presets card's third line. It goes once a fight ends, the list changes, or Autotune or the city switch starts (`CardState` in UI.lua). `/ec back` goes back one step, the newest, and prints it. Compare's "before" is the newest preset step (`ns.BeforeRecord`). Checks in `tests/test_back_history.py` and `tests/test_back_after_changes.py`.
- **Sliders.** Every numeric setting has a slider (`ns.Slider` in UI.lua): a typed box, arrows, Shift for fine steps, the wheel for one step once the bar is clicked, a gold tick at the game default and a reset arrow. Render scale runs over the game's own range (`GetMinRenderScale` to `GetMaxRenderScale`, 33% to 200% before a game update on 14 Nov 2026 capped the top at 100%) in 1% steps. Sharpness has an Off position (-1).
- **Tooltips.** Every dial, Extra and Standard tooltip is built by `ns.SettingTip` (UI.lua): Blizzard's words, then the plain line, then the game default (checks in `tests/test_tooltips.py`).
- **Bug reports.** `/ec report` builds one block of text: addon version, game build, settings and recent Lua errors caught by wrapping the game's error handler (`Report.lua`, checks in `tests/test_report.py`).
- **Refusals show in the window** (rule 6 of `docs/ui-rules.md`, checks in `tests/test_refusals.py`). A refused Duplicate, Share, Rename, Delete or Save shows on the Presets card's third line (`Said` in UI.lua, cleared like Back's result). A refused Create backup shows on the Backups tab's result line, or elsewhere on the red line above the bottom bar. That line (`ns.BarSay`) also says a refused Compare or Peek, and Apply with nothing to apply (`ns.BarApply`). It goes when you change tab, shrink or open up, press another bar button, or Compare flips. A Standard or Hidden setting refused in a fight says "not changed in a fight" in red on its own row until the fight ends, through other refreshes (`SetStandard`, `SetAdvanced` and `ResetAdvanced` return `false, reason`; the row keeps it in `refused`). A dial's reset arrow in a fight changes nothing, not even your saved value. And the game-menu button says why under itself (`tests/test_refusals_rows.py`). Chat keeps the slash commands and a closed window.
- **Autotune (experimental).** The Experimental tab. It measures FPS from `OnUpdate` frame times (the game has no CPU, memory or refresh-rate API, checked Nov 2026), drops the settings in `AT.KNOBS` to their lowest, then raises one at a time and keeps a raise only if the goal still holds (10% to spare, and the slowest 5% of frames at 85% of the goal). A measurement leaves out a long frame or two and is taken again once if it had one; settling waits until FPS stops moving, and a try far from its line stops early (`AT.Stats`, `AT.Early`). FPS held at a refresh rate at the lowest settings is a cap (`AT.Cap`): a goal at it is judged just under it, one above it is unreachable. Render scale at 100% is measured next; hardly slower than the lowest means CPU-bound, and the `cpu` settings then keep 25% spare (`AT.Line`). A goal takes the best stretch of steps for the look per cost; Best balance takes render scale (`free`) to 100% first, then steps while the FPS cost is small for the look added. Render scale over 100% goes last. The ways of tuning are `AT.STYLES` (Tune for on the tab, remembered with the goal in `EyeCandyDB.autotuneGoal.style`); each only changes the numbers above. Raid ready keeps 50% spare (80% for the `cpu` settings on a CPU-bound PC) and the slowest 5% at the goal itself. Smooth holds the slowest 5% at the goal and the slowest 1% at 70%, measures 6 seconds, calls a close call on the slow frames and never stops a sample early on a pass. Sharpest picture tries the `clear` settings first, render scale over 100% straight after them, and is the only one that moves anti-aliasing and sharpening (`only`; CMAA and CMAA 2 only where `AntiAliasingSupported()` says so). Cool and quiet tunes as Best look, then turns the game's FPS cap on at the goal (`useMaxFPS`, `maxFPS`, read back; if the game keeps another number, yours goes back and the result says so); it needs an FPS goal. The cap is your own setting, never part of the preset, so Save as preset sets it again after the preset goes on and says so, the preset's note leaves it out (a copy or a share code carries the note), and Back to before Autotune puts your old one back. A cap that lowers a way of tuning's own line is reported (`AT.result.cap`), so Raid ready never claims spare it couldn't keep. After every 8 tries, and at the end unless the last try passed, the kept settings are measured again. If they no longer hold, the newest raises go one at a time until they do; out of measurements, it goes back to what the last passing check measured. A check on the way allows 3%; the last one doesn't. Costs are kept in ms a frame and shown in FPS at the result's rate. The look and cost numbers in `AT.KNOBS` are guesses that only set the order. The settings from before are saved in `EyeCandyDB.autotune` first; moving, turning, dragging or zooming the camera (`IsMouselooking`, the left button held and moved over the world, `GetCameraZoom`), a loading screen, Options or another Eye Candy apply stops it and puts them back, and so does the next login after a crash. Combat stops it too, and the put-back waits for the fight to end, as do Save as preset and Back to before Autotune. Save as preset saves a user preset, whose `desc` (its tooltip) says where it was tested: zone, subzone, map position, facing, field of view and camera distance (`AT.Place`, `AT.PlaceText`; an instance hides position and facing). A copy and a share code carry it (`DuplicatePreset`, and the share payload's `desc`, cut to 400 characters and cleaned on import). The game has no camera pitch for addons. While Autotune has your settings, `ns.AutotuneNote()` gives one line, and the window's title and the Presets card's third line show it (`ns.RunningNote` in UI.lua, which says the city switch's instead when Autotune is idle). Status lines are `AT.Say(kind, text)`: done normal, waiting grey, refused red; chat only when the Experimental tab isn't in front. Start from (on the tab, `EyeCandyDB.autotuneGoal.from`, a preset id; a deleted one falls back to the lowest settings) runs differently: `AT.NewRun`'s `from` gives each setting the steps from its lowest up to the preset's value (a value between steps is a step of its own; render scale's steps over 100% join it; "after" settings are left out), the preset's values go on with `ns.PresetValues` and `ns.ApplyValues`, and while the goal misses, the setting whose current step has the least look for its cost goes one step down (Sharpest picture lowers the non-`clear` ones first). Nothing is raised. A cap is never taken from the heavy preset alone (it may just run at an even 60): after a step that gains nothing with frames even at a refresh rate, one measurement with everything it may lower at its lowest tests it, and only if FPS stays there is it a cap (the step then goes back). The preset's essence is never lowered: a Look keeps what its description names (`AT.LOOK_KEEP`), anything else keeps the settings clearly above its others (`AT.Essence`: more than 0.25 over the middle share of their scale). Best balance from a preset, once 60 holds, lowers a setting one step only where it gains more than 4% FPS a point of look, never render scale. The preset's other values are set again after each change (a menu value can reset hidden ones), the result is named for the preset ("Moody for 120 FPS"), and Save as preset keeps the preset's values for what wasn't tuned, with "Started from Moody." in its note. Pure logic is `AT.Step` and friends (checks in `tests/test_autotune.py`, the ways of tuning in `tests/test_autotune_modes.py`, start from a preset in `tests/test_autotune_from.py`, the pretend PC they use in `tests/autotune_sim.lua`).
- **Patch warning.** At logout and /reload (`ns.PatchWatchLogout`, from Core.lua) a copy of every setting on the list goes in `EyeCandyDB.patchWatch.snap`, as your own values (`PW.Own`: Compare's "now", the settings from before Autotune, `ns.SituationValue`). About 8 seconds after login (`ns.PatchWatchLogin`; after a fight if in one) it compares. Only a change made while the game was closed shows, in one window with Put them back and Keep the game's; none, nothing shows. It stays quiet with no copy (first login), another graphics card (a copied settings folder), another account's token in the `eyeCandyWatch` CVar, a setting stored on the server, and the same change as last time (something rewrites it at every start). The token lasts across a relog, not a game close, so another account that played in an earlier game run can still cause one false warning. A logout or /reload before the check keeps the old copy for each setting the session left alone. Put them back uses `ns.ApplyValues` with its options inside `ns.KeepSituationLowered`, reads each back, says in red any the game kept, waits out a fight and takes no backup (checks in `tests/test_patch_watch.py`).
- **Help me pick.** A button on the Quality levels heading (`ns.HelperButton`, placed by `RefreshPresetList` in UI.lua) opens a strip under it with one question. It never opens by itself: no popup, no line at login, nothing in chat. Prettier and Faster move one step along `H.LADDER` (Laptop, Performance, Balanced, High, Ultra, Beautiful, Showcase) from where you are: a built-in you haven't changed by its step (`H.NEAR` places the ones off the ladder), anything else by measuring the Graphics menu settings and render scale against the quality levels (`H.Level`; render scale counts 4 times and is taken as the game would keep it). The strip says what the pick changes (`H.Changes`; a quality level leaves a render scale override alone, so it isn't listed) and its Apply is the row's own (`ns.PresetAction`). In a fight it waits for the fight to end and says so; closing the strip or leaving the tab drops the wait. Let Eye Candy pick sets `EyeCandyDB.autotuneGoal` to Best balance and Best look, opens the Experimental tab and says to press Start; it starts nothing. Checks in `tests/test_helper.py`.
- **Live FPS** (`FPS.lua`, checks in `tests/test_fps.py`). `ns.FPS.Watch(key, fn)` starts the reader; `fn(now, raw, frames, seconds, longest)` runs twice a second (`FPS.EVERY`) with the smoothed FPS (`FPS.Smooth`, half way to each new reading), that reading's FPS, its frame count and length, and its longest frame in seconds (a hitch). A reading of one frame over 2 seconds (`FPS.STALL`, a loading screen) is dropped. Watching again with the same key replaces `fn`; `fn` may unwatch itself but must not watch a new key. `ns.FPS.Unwatch(key)` stops; the last one out hides the reader's frame, so with nobody watching it costs nothing. `ns.FPS.Now()` is the smoothed FPS, nil while nobody watches. `ns.FPS.Shown(shown, now)` gives a whole number that moves only once `now` is 0.75 away, so a label never flickers. The bottom bar's number (`main.fps`, grey) watches as `"bar"` while the window can be seen (closed, Peek or Alt+Z stop it: `IsVisible`) and sets its text only when that number changes. It sits left of Peek; shrunk, at the left of the title row, hidden while the title (a Compare label) needs the room (`FPSFits` in UI.lua). Each preset applied (`ns.NoteOnPreset`, wrapped in FPS.lua), except by Autotune while it runs, starts one measurement, watching as `"preset"`: it settles as Autotune does (at least 3 seconds, two readings within 3%, at most 10), then takes 4 seconds of frames, leaving out one long frame a reading while that is under 1% of them. It starts over whenever you aren't still (`FPS.Still`: a fight, moving, turning, the camera zoomed or dragged, the left button held, Options open, Compare or Autotune running), gives up after a minute, ends on a loading screen, and keeps nothing unless the preset is still on with nothing changed (`ns.OnPreset`). The result is `EyeCandyDB.presetFPS[id] = { fps, zone, at }`, the zone being the subzone where there is one. The preset row's tooltip ends with `ns.FPS.PresetLine(id)` ("Last time: 63 FPS in Goldshire."). Deleting your preset deletes its number.
- **The Experimental tab's parts.** A row of buttons at the top of the tab picks the part on show (`ns.EXPERIMENTS`, remembered in `EyeCandyDB.experimentPart`); each part has its own scrolling page. Autotune is first.
- **Eye test (experimental).** Ten rounds, each flipping one setting between two values far enough apart to see (`ET.ROUNDS` in EyeTest.lua). Which is 1 and which is 2 is random each round. You flip freely; the answers wait until you have seen both. "Same to me" keeps your own value. An answer stays on for the rounds after it. A round whose setting the game lacks, or whose sides step down to the same value, is left out (`ET.Resolve`). Your settings are saved in `EyeCandyDB.eyeTest` first. A fight, a loading screen, Options, closing the window (not Peek), Stop or any other Eye Candy apply ends it and puts them back; in a fight already locked, after it; a test still saved at the next login, then. An answer sets your settings from before again with the answers on top (a menu value can reset hidden ones). A preset's record of before (`NoteBeforePreset`) and every restore end it first too, and Options notes the game menu's values again once yours are back. At the answers, the fight puts your settings back but keeps the answers, so Save as preset still works. Save as preset saves your settings from before with the answers on top, puts yours back, then applies the preset (so its backup and Back to before hold yours). Compare and Autotune refuse to start during it, and it refuses while Autotune has your settings. `ns.RunningNote` says it has your settings. Checks in `tests/test_eye_test.py`.
- **Photo mode (experimental).** Take photo puts the Screenshot preset's values on (`ns.PresetValues`, then `ns.ApplyValues`, so no Back to before record and no backup), hides the screen with no Back bar (`ns.PeekWithoutBar` in Peek.lua; if the game's UI won't hide, nothing stays hidden and no photo is taken), waits for the new settings (`PM.Settle`: 2 to 6 seconds as Autotune after a render scale change, until two half-second windows in a row are even, no frame over 2.5 times the average, with frame rates within 10%; a rule of thumb, counting the frames), then calls `Screenshot()` and waits up to 5 seconds for `SCREENSHOT_SUCCEEDED` or `SCREENSHOT_FAILED`. Then the peek ends and your settings go back; the result says so only once they are (a fight already locked: after it), and says the UI may be in the photo if Esc came while the game took it. The city and instance switch waits during a photo (a wrap of `ns.UpdateSituations`) and looks again once your settings are back; the eye test does the same. Addons may call `Screenshot()` (Memento does on retail); not tested on Forever itself. The file goes to the Screenshots folder in `_forever_` (warcraft.wiki.gg). Your settings are saved in `EyeCandyDB.photo` first; a fight, a loading screen, Esc (the peek ending) or any other Eye Candy apply stops it and puts them back; in a fight already locked, after it; still saved at the next login, then. Compare, Autotune and the eye test refuse to start during a photo. The patch warning's copy and the FPS reader leave its values alone (wraps of `ns.PatchWatch.Own` and `ns.FPS.Still`, as the eye test does). Checks in `tests/test_photo_mode.py`.
- **Releases.** A `v*` tag runs the BigWigs packager (`.github/workflows/release.yml`). It uploads to CurseForge and Wago using the project IDs in the .toc and the tokens kept in the repository's `release` environment.
